# Data

## Impact note (for judges)

This folder is a **demo corpus**, not a customer dataset. Hands-on “h/week” figures derived from it exercise the Priority Critic (evidence-capped ranking). They are **not** AgentOffice’s claim of value. Product impact is: filled spreadsheets, Arabic-aware lookups, QA + code-hash approval — see the README Impact section.

## `sample/workforce/` (synthetic)

All of it is **synthetic**. The people, emails, tickets and activity are invented. Emails use the reserved `example.com` domain. No real or personal data is included.

- **Origin:** generated by [`scripts/generate_workforce_data.py`](../scripts/generate_workforce_data.py) with a fixed seed, so it's deterministic. `--check` verifies that the committed files match the generator.
- **Licence:** none granted. Like the rest of this repository, the data is the team's own work, produced by the generator above; no third-party data is included.
- **Period:** six working weeks, 2026-08-31 to 2026-10-09. Row counts and checksums are in `manifest.json`.

| Table | What it holds |
|---|---|
| `people` | 12 invented employees across Finance, Operations, Sales and Admin |
| `timesheets` | Self-reported hours per task category per day |
| `tickets` | Ticket-system records with the minutes people logged |
| `email_events` | Email metadata only (direction, counterparty type, category); no bodies |
| `task_events` | Application activity log, one row per action, grouped by `case_ref` |

The generator plants patterns for the agents to find. It doesn't plant answers.

- Repeated multi-step routines in `task_events`, such as invoice matching.
- Timesheet hours that disagree with ticket logs for some task categories.
- Inbound vendor invoices that trigger the invoice routine.

The agents still have to discover, quantify and explain these from the rows.

To regenerate:

```powershell
.\.venv\Scripts\python.exe scripts\generate_workforce_data.py
```

## How the data reaches Zetaris

Zetaris can't read files on this machine. The API serves each table as JSON at `GET /data/workforce/<table>`, and [`scripts/load_zetaris.py`](../scripts/load_zetaris.py) registers those endpoints as Lightning REST tables. It's a dry run by default; add `--apply` to execute. In sample mode, the same CSVs are loaded into SQLite under the same `workforce` name instead.

## `sample/tasks/` (synthetic demo spreadsheets for task mode)

Generated by [`scripts/generate_task_samples.py`](../scripts/generate_task_samples.py) with a fixed seed. Every person, email and company is invented (`example.com` / `example.org`).

| File | What it holds | What it's for |
|---|---|---|
| `expense_claims.xlsx` | 40 claims: mixed date formats, messy categories, blank Team and Role columns; the emails are the synthetic staff from `people` (in mixed case and spacing), plus two that are not on staff | looking up team and role from Zetaris, tidying, dates, GST, flags, totals |
| `vendor_invoices.csv` | 30 invoices plus 4 re-typed duplicates, some blank statuses | dedupe, fill blanks, flag overdue, sort |
| `leads_and_contacts.xlsx` | a `Leads` sheet (25) and a `CRM Contacts` sheet (13, including a duplicate email) | split names, look up another sheet, statuses |

The API stores them on start-up as uploads `demo_<name>`, so they are also rows in the Zetaris table `upload_cells`.
