A problem generic tools miss. In the UAE and Saudi Arabia one spreadsheet can hold the same staff ID typed in Western, Arabic-Indic or Persian digits, and the same name spelled two ways, so a plain lookup quietly misses rows. In AgentOffice this is part of the reasoning, not a filter bolted on. The Data Profiler notices the variants while it queries your file through Zetaris. The PM puts the arabic_digits normaliser on the lookup key; if it leaves it out, the Spec Critic finds that the keys only match after normalising, rejects the plan and names the fix. QA then swaps digits, spellings and separators in its test cases and requires the same result. On our bundled UAE demo, 17 of 18 claims match the staff directory, and the one ID that is not on staff is flagged rather than guessed.
